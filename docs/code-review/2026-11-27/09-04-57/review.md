# コードレビュー結果

- 実行日時: 2026-11-27 09-04-57
- 対象: `feature/split-releases-unified-update`
- ツール: Open Code Review
- 結果: 12件の指摘を確認。レビュー後半はキャンセルされたため、確認済みの指摘を基準に修正し、別途Swift・リリース処理のレビューとテストを実施した。

## 指摘への対応

| 指摘                                                     | 判断 | 対応                                                            |
| -------------------------------------------------------- | ---- | --------------------------------------------------------------- |
| テストスクリプトを実行ビット前提で直接実行している       | 採用 | ワークフローでは `bash` 経由で実行する。                        |
| pushとpull_requestでツールリリーステストが二重実行される | 採用 | pushのみにし、concurrencyで古い実行をキャンセルする。           |
| ツールReleaseのタグを任意に変更できる                    | 採用 | 本番ワークフローのタグ入力を削除し、`tools-latest` に固定する。 |
| ツール準備失敗時も「更新を確認中」が表示される           | 採用 | 準備完了前の確認中表示は隠し、オーバーレイに任せる。            |
| 統合更新ボタンの当たり判定が文字列部分だけになる         | 採用 | 背景を消しても padding は残す。                                 |
| ツールリリーステストにタイムアウトがない                 | 採用 | 15分のタイムアウトを設定する。                                  |
| 検証ジョブの権限が最小化されていない                     | 採用 | `contents: read` を明示する。                                   |
| アプリReleaseがツールマニフェストのHTTP 200だけを見る    | 採用 | スキーマ、必須7ツール、URL、SHA-256、参照assetを検証する。      |
| 初回復元の欠落判定がモデルを見ない                       | 採用 | ツール単位の整合性判定に `upscal/models` を含める。             |
| 片方の確認失敗で既知の更新まで隠れる                     | 採用 | アプリ・ツールの失敗を区別し、確認済みの更新を優先表示する。    |
| 同じ理由で統合カード全体が消える                         | 採用 | 前項と同時に修正する。                                          |
| 任意ブランチからツールを公開できる                       | 採用 | mainのみを許可し、新規タグ先を実行コミットにする。              |

## 追加レビューで確認した事項

- ツール更新と変換の競合を防ぐため、変換中は更新を開始せず、ツール更新中は変換とドロップを受け付けないようにした。
- 複数ウィンドウでの初回準備・更新の競合を防ぐため、関連モデルをアプリ側で共有するようにした。
- 空・不正なSHA-256、実行中と失敗カードの優先順、手動確認中の操作、ツール名の進捗表示を修正した。
- アプリReleaseはDraftに全assetを添付し、ダウンロード検証後に公開するようにした。
- ツールReleaseはモデル・dylib・LFSポインタを検証し、同名assetの異なる内容を上書きしないようにした。
- リリース後再実行、欠落マニフェスト、URLホスト、古いasset削除のAPI失敗、ビルド番号のフォールバックを強化した。
