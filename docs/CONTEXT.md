# CONTEXT

このドキュメントは `tree-image-optimizer` の**現在のアーキテクチャ俯瞰**です。
新規参加者が全体像を掴むための入口として、実装に基づく事実のみを記述しています。
個別の技術的決定の理由は [ADR INDEX](./adr/INDEX.md) を参照してください。
実装上のクラス名・関数名は記載せず、役割で表します。

## プロジェクトの目的

macOS 向けデスクトップアプリです。フォルダ内の画像を**一括で並列に最適化**します。

最適化は次の2段階です。

1. **アップスケール**: 超解像技術で1〜4倍に拡大する
2. **圧縮**: JPEG / PNG / JPEG XL / AV1 / WebP で圧縮する

ユーザーは「フォルダを選択 → アップスケール種別を選択 → エンコード種別を選択」して一括変換を実行します。
1ファイルだけを手軽に変換する「かんたん変換」もあります。

画面仕様は [docs/design/feature/](./design/feature/) に、システム全体の設計は [docs/design/system.md](./design/system.md) にあります。

## 全体アーキテクチャ

レイヤは View → Model → Service の**一方向**で、Apple 推奨の Observation ベースです。
UseCase / Repository 層は設けず、オーケストレーションは Service に集約して層を薄く保ちます。

| 層      | 責務                                                                            |
| :------ | :------------------------------------------------------------------------------ |
| App     | アプリのエントリポイントと画面の骨格                                            |
| View    | 宣言的UI。業務状態は持たず Model を表示・操作に結びつける                       |
| Model   | 観測可能な画面状態と実行指示を持ち Service を呼ぶ                               |
| Service | 永続化・外部プロセス・OSフレームワークの薄いラッパー。UI 判断ロジックを持たない |
| Core    | 機能横断の共有物（データ定義・エラー型・テーマ・文言解決）                      |

### 状態管理の要点

- UI状態は観測可能な状態として保持し、メインスレッドに隔離します。Service はスレッド安全にし、
  非同期処理は構造化並行処理で記述します。
- **共有状態**（設定・アプリ本体の更新確認・一括変換ジョブ・かんたん変換ジョブ）は
  アプリのエントリポイントで生成し、ルート画面経由で各画面とサイドナビへ**同一インスタンス**を
  渡します。ツール更新と初回展開の状態はルート画面が保持します。これにより画面遷移で
  View が再生成されても実行状態が維持され、孤児タスクになりません。
- **実行状態**は画面ごとのローカル状態ではなく、共有のジョブ層が持ちます。

## 変換パイプラインの流れ

処理は `フォルダ選択 → アップスケール → 圧縮 → 出力` の順です。フロー図は
[docs/design/feature/convert-flow/](./design/feature/convert-flow/) にあります。

1. **対象ファイル選定**: 入力フォルダを走査します。拡張子は `jpg` / `jpeg` / `png` / `webp` の
   **静止画のみ**で、更新日数による絞り込みもここで行います。
2. **変換計画**: 各ファイルの寸法とサイズから倍率・縮小先・品質を決めます（固定モードは
   全ファイル共通、自動モードはファイルごとに最適化。ADR 0049）。
3. **アップスケール**: 外部バイナリを呼びます。GPU バウンド。
4. **圧縮**: 各エンコーダを呼びます。CPU バウンド。
5. **出力**: 中間ファイルを出力先へ確定します。

### ステージ別ワーカーと並列数

アップスケールと圧縮は**別々のワーカー群**として動き、間をキューでつなぎます。
片方の完了を待たずにもう片方が次々と処理できるため、GPU と CPU が同時に使われます（ADR 0034）。

- 並列数（スライダー値）を GPU と CPU に配分します。アップスケールを最大3に抑え、
  残りを圧縮へ回し、小さな並列数でも最低1ずつ確保します。
- アップスケールは**最大4ファイルを1プロセス**にまとめ、ディレクトリ一括実行でプロセス起動の
  固定費を削ります（ADR 0035）。バッチは同じ倍率・縮小先のファイルだけで組み、自動モードでも
  一覧表の上から順に最大8件を先読みしてまとめます（ADR 0053）。
- **処理枠**は並列数ぶんです。枠はアップスケール完了では空かず、**出力が完了したときだけ**
  空きます（ADR 0038）。
- エンコーダに渡す総スレッド数は並列数ぶんで、それを圧縮ワーカー数で割って各プロセスへ配ります。
  そのためスライダーの位置がそのまま CPU 負荷の目安になります（ADR 0039）。既定値は
  Pコア数の半分です（ADR 0036）。
- 実行中は**一時停止とキャンセル**ができます（ADR 0054）。キャンセルは実行中の外部プロセスを
  終了し、出力済みファイルは残します。

## 主要な役割の対応関係

| 役割                     | 責務                                                                                     |
| :----------------------- | :--------------------------------------------------------------------------------------- |
| 変換オーケストレーション | 変換全体の進行。ワーカー群・スケジューラ・キューの生成と集計                             |
| アップスケール実行       | 外部アップスケーラの呼び出し、エンジンの振り分け、実行前後の検証                         |
| 圧縮実行                 | フォーマット別のエンコーダ呼び出しと引数組み立て                                         |
| 一括変換ジョブ           | 一括変換の実行状態（進捗・結果表）を保持し、実処理をオーケストレーションへ委譲           |
| かんたん変換ジョブ       | かんたん変換の実行状態を保持                                                             |
| 変換設定                 | 両画面で共有する変換設定の保持、保存、実行用スナップショットの生成                       |
| 対象ファイル選定         | 拡張子と更新日数による対象ファイルの絞り込み                                             |
| 変換計画                 | ファイルごとの倍率・縮小先・品質の決定                                                   |
| パス解決                 | ツール・設定・ログなどのパス解決                                                         |
| 設定の永続化             | 設定ファイルの読み書きと補正                                                             |
| ツール準備               | 外部ツールの初回展開と修復                                                               |
| ツール更新               | 配布メタデータとの差分検出と、ツール単位の更新                                           |
| アプリ更新               | 更新確認、ダウンロード、検証、適用                                                       |
| 共通エラー               | アプリ共通のエラー表現                                                                   |

変換設定から作る**実行用スナップショット**を使い、実行中に UI の設定が変わっても処理が
ぶれないようにします。

## 外部ツールの配置とインストール

変換処理はすべて**外部バイナリのサブプロセス**として実行します。

ツールはリポジトリの `tools/` 配下に置き、実行時は
`~/Library/Application Support/tree-image-optimizer/tools/` に展開されます。

| 用途                   | バイナリ                | 配置                                                   |
| :--------------------- | :---------------------- | :----------------------------------------------------- |
| アップスケール         | `upscayl-bin`           | `tools/upscal/bin/`（モデルは `tools/upscal/models/`） |
| アップスケール（必須） | `realcugan-ncnn-vulkan` | `tools/realcugan/bin/macos/`                           |
| JPEG 圧縮              | `jpegoptim`             | `tools/jpegoptim/bin/macos/`                           |
| PNG 圧縮               | `pngoptim`              | `tools/pngoptim/bin/macos/`                            |
| JPEG XL 圧縮           | `cjxl`                  | `tools/libjxl/bin/macos/`                              |
| AV1 圧縮               | `avifenc`               | `tools/libavif/bin/macos/`                             |
| WebP 圧縮              | `cwebp`                 | `tools/libwebp/bin/macos/`                             |

- アプリ本体の配布ZIPは tools を同梱しません。tools はツール単位のZIPと
  `tools-info.json` を事前リリースの `tools-latest` で別配布し、起動時の差分判定で更新します（ADR 0078）。
- 初回起動時はツール準備処理が存在チェックを行い、揃っていなければ修復します。完了まで
  操作はブロックされます。
- 修復は**開発用ローカルの `tools/` コピーを優先**し、使えない場合は `tools-latest` から
  不足ツールをSHA-256検証付きで取得します。
- ツール準備の完了後に `tools-info.json` を取得し、`tools/.installed.json` とバージョンが
  異なるツールだけをヘッダー右端の統合更新ボタンで通知します。
- libjxl は依存 dylib ごと `@loader_path` で解決する形で同梱します（ADR 0017、ADR 0056）。
- Real-CUGAN は必須ツールです。実行前に `.param` と `.bin` のペアを確認するのは、
  欠けていてもバイナリが終了コード0で黒画像を出すためです。

## 設定の保存

設定は `~/.config/tree-image-optimizer/settings.json` に保存され、次回起動時に復元されます。

- トップレベルは `settings` / `batchConvert` / `easyConvert` の3セクションです。
- `batchConvert` は一括変換画面、`easyConvert` はかんたん変換画面の設定で、**独立に保存**されます。
- ファイルが無い・壊れている場合は初期値を保存して返します。不正値は補正し、旧形式のキー
  （`convert` / `batch` / `easy`）は新形式へ移行します。

ユーザーが任意に配置する資産も同じディレクトリ配下です。

- `~/.config/tree-image-optimizer/sounds/success` : 成功時のサウンド
- `~/.config/tree-image-optimizer/sounds/error` : 失敗時のサウンド
- `~/.config/tree-image-optimizer/wallpaper` : 背景画像

いずれもアプリの再起動で読み込まれます。ログは
`~/Library/Application Support/tree-image-optimizer/logs/` に出力されます（ADR 0047）。

## アップデート

- **アプリ本体**は GitHub Releases の「Latest」にある `update-info.json` を比較し、ZIPを
  ダウンロード・SHA-256検証・展開して再起動用にステージングします。ステージング後は緑の
  `アプリ再起動する` ボタンから配置と再起動を行います（ADR 0076）。
- **ツール**は `tools-latest/tools-info.json` と `tools/.installed.json` の差分だけを
  ツール単位ZIPで更新します。アプリ本体のReleaseとは別に配布し、ツールだけの更新では
  再起動しません（ADR 0078）。
- ヘッダー右端の更新ボタンは1個に統合します。両方に更新がある場合はツール→アプリの順に
  実行し、失敗時は赤いカードから未完了の更新を再実行できます（ADR 0078）。

## 対応フォーマット

### 入力

アプリが受け付ける**静止画のみ**です。

- `jpg` / `jpeg`
- `png`
- `webp`
- `heic` / `heif` / `avif`

`gif` とアニメーション形式（APNG 等）は対象外です。外部アップスケーラがアニメーションを
マルチフレームとして扱わず先頭フレームだけを読み出すためで、入力フィルタで対象外にして
静止画前提を保っています。詳細は [ADR 0063](./adr/0063-post-verify-still-image-only.md) を
参照してください。`heic` / `heif` / `avif` は静止画として受け付け、アップスケールの直前に
中間 PNG へデコードして処理します（ADR 0069）。

### 出力

出力フォーマットは5種類です。既定は JPEG XL です。

| フォーマット | 拡張子  | エンコーダ                         |
| :----------- | :------ | :--------------------------------- |
| JPEG         | `.jpg`  | 標準画像処理で生成後に `jpegoptim` |
| PNG          | `.png`  | 標準画像処理で生成後に `pngoptim`  |
| JPEG XL      | `.jxl`  | `cjxl`                             |
| AV1          | `.avif` | `avifenc`                          |
| WebP         | `.webp` | `cwebp`                            |

出力ファイル名は入力名の**最初の `.`** より前をベースにし、出力フォーマットの拡張子を付けます。
同名ファイルが既に存在する場合は置き換えます。最適化種別ごとのパラメータは
[docs/design/feature/convert-flow/compression.md](./design/feature/convert-flow/compression.md) にあります。

## 開発フロー

### 環境構築

`./setup.sh` で Homebrew 依存（Brewfile）、git hooks（prek）、VSCode 拡張を導入します。

### 変更後の検証手順

AGENTS.md の順序に従い、次の順で実行します。

```shell
swiftlint                                       # 規約違反の検出（自動修正は --fix）
swift format format -i -r TreeImageOptimizer    # フォーマット
xcodebuild ... build                            # コンパイルエラーの確認
```

設定はリポジトリ直下の `.swiftlint.yml` と `.swift-format` で管理します。
`swift-format` は Xcode ツールチェーン同梱のため追加インストールは不要です。

Markdown を修正した場合は `rumdl` を使います（`./tools/rumdl.sh` 経由でも可）。

```shell
rumdl fmt      # フォーマット
rumdl check    # lint
```

### git hooks

`prek` で commit 時に次が走ります（ADR 0044）。

- `rumdl fmt` : Markdown の整形。差分が出たら commit が中断されます。
- Betterleaks : ステージ済み差分の機密情報チェック。

hooks は GUI から commit しても動くよう、`tools/` 配下のラッパースクリプトを経由します。

### ADR の運用

技術的な決定・変更は **`docs/adr/` に ADR として記録**し、[INDEX.md](./adr/INDEX.md) に追加します。
判断の理由を残すことが目的のため、「何を決めたか」だけでなく「なぜ他の案を採らなかったか」も書きます。

### ブランチとコミット

- コミットメッセージは [Conventional Commits](https://www.conventionalcommits.org/ja/) に準拠し、
  **日本語**で記述します。Why を書きます。
- コードには How、テストコードには What、**コードコメントには Why not** を書きます。
- main ブランチへの直接 push は禁止で、feature ブランチから PR を作成します。
- PR 作成前に [コードレビュー](./design/code-review.md) します（対象は Swift 関連のみ）。
- Xcode のバージョンは `.xcode-version` で管理します。
