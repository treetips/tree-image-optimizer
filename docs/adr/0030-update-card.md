# サイドナビ下部の更新カードを更新の有無で表示し分ける

## ステータス

- 承認済み (Accepted)

## 背景・課題

ADR 0014/0015 で更新確認の起動経路（メニュー・起動時・About）を整えた。
起動時のサイレント確認は「更新あり」のときだけサイドナビに通知を出していたため、
ユーザーは通知が出ないとき「確認したのか・更新が無いのか」が分からなかった。
仕様（`docs/design/feature/update-application.md`・旧 `sidenavi.md`）として、
更新カードは更新の有無の双方で出し、更新なしは一定時間で自動的に消すことになった。

## 決定

- サイドナビ最下部に更新カード (`UpdateCard`) を表示する。
    - 更新あり (`available`): 背景色はOSテーマカラー（アクセント色）。クリックで
      インストール確認ダイアログを開く（サイレント確認結果を元にし、再確認しない）。
    - 更新なし (`noUpdate`): 背景色は透明に近い目立たない色。クリックでカードを
      非表示化する。
- 両カードともLiquid Glassで表示する。`.glassEffect` の tints は既存パターンに
  合わせ半透明アクセント色で重ねる（不透明な塗りはグラスを飽和させてベタ塗りに
  見えるため）。濃さ・角丸は `GlassStyle` に一元化する
  （`updateCardTintOpacity` / `updateCardNoneTintOpacity` / `updateCardCornerRadius`）。
- 更新なしカードは10秒後に自動で非表示化する。定数は
  `UpdateCheckController.noUpdateCardHideSeconds`。
- カード状態は `UpdateCheckController.card` に持ち、起動時のサイレント確認
  (`refreshAvailability`) で解決する。確認失敗も「更新なし」扱いで表示する。
  クリック非表示・10秒後の自動非表示・カード差し替えの間のタイマー競合は、
  状態の差し替え時に必ず旧タイマーをキャンセルして防ぐ。
- 旧通知用プロパティ `updateAvailableInfo` は `card` に統合して削除する。
- 更新確認結果→カード状態の解決は `UpdateCheckController.resolveCard(for:)` と
  いう純粋関数に切り出し、単体テストで検証する。

## 代替案

- 更新ありのときだけカードを出す（旧実装）
    - 却下: 更新なしの表示が無く、確認したかどうかがユーザーに伝わらない。
- 更新ありカードのクリックで再度ネットワーク確認してからダイアログを出す
    - 却下: カードクリックのたびにネットワーク通信と待ち時間が発生し、
      起動時の確認結果が無駄になる。サイレント確認済みの情報をそのまま使う。
- タイマーをView側 (`onAppear` + `Task`) で管理する
    - 却下: 更新カードの表示条件がコントローラの状態一つにまとまらず、
      カードが消えた後にタイマーが残る崩れが起きやすい。状態側で止める方が堅い。

## 結果

- 更新カードが更新の有無で表示し分けられ、更新なしはクリック・10秒経過の
  どちらでも非表示化される。
- 実装箇所: `Core/UpdateCheckController.swift`・`App/RootView.swift`・
  `Resources/Localizable.xcstrings`（`nav.updateNone`）。
- テスト: 確認結果→カード状態の解決と、更新なしカードの文言の単体テストを追加。
