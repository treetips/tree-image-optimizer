# GitとGitHubの運用ルールを別ドキュメントに分割する

## ステータス

- 承認済み (Accepted)

## 背景・課題

`docs/design/git.md` には、コミットメッセージやブランチ命名のような Git の操作ルールと、
PR のタイトル・ラベル、リリースタグのような GitHub 上の運用ルールが混在していた。
ルールの置き場所は曖昧だった。追加のたびに、Git と GitHub のどちらの関心かを読み解く必要があった。

## 決定

`docs/design/git.md` を Git の操作ルールに限定し、GitHub 上の運用ルールを
`docs/design/github.md` へ分ける。

- `git.md`: コミットメッセージ、ブランチ命名規則、既存コミットの扱い、worktree を使った同時進行。
- `github.md`: ブランチ運用（`main` への直接push禁止）、PR 運用（タイトル・ラベル・レビュー）、
  リリースタグ、スタックプルリクエスト、エージェントが作成した PR のマージ。
- リリースタグは `vMajor.Minor.Patch` の命名規則も含め、GitHub Actions による自動作成と
  一体で扱うため `github.md` に置く。
- 両ファイルの冒頭で相互にリンクし、`docs/CONTEXT.md` の関連ドキュメントにも `github.md` を追加する。

## 代替案

- **1ファイルのまま見出しで区切る**: 見出しの位置は分かるが、ルールを追加するときに
  Git と GitHub のどちらかを判断する負担は残る。
- **`release-flow.md` に PR・タグのルールを統合する**: リリース手順と日常の PR 運用は
  読む場面が異なり、手順書に運用ルールが埋もれる。
- **タグの命名規則を `git.md` に残す**: タグの作成は Release ワークフローが担うため、
  命名と作成の記述が2ファイルに分かれて参照が増える。

## 結果

- Git のルールと GitHub のルールを、それぞれの関心ごとに探せるようになった。
- 新しいルールはどちらのファイルへ書くかを決めやすくなった。
- PR・タグの既存ルールは `github.md` へ移し、`docs/CONTEXT.md` の関連ドキュメントから両方へ辿れるようにした。
