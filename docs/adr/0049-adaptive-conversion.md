# 画像ごとに目標解像度と圧縮品質を決める自動最適化を追加する

## ステータス

- 承認済み (Accepted)

## 背景・課題

一括変換は拡大率と品質を全ファイル共通の固定値で実行していた。
そのため、次の2つの問題があった。

- 縦横が大きい画像は目標より大きく拡大され、処理時間とファイルサイズが無駄に増える。
- 縦横が小さい画像は拡大が足りず、壁紙にするとぼやける。
- ファイルサイズが大きい画像は圧縮が弱く、小さい画像は既に圧縮済みなのにさらに圧縮されてぼやける。

拡大率は結果であり、ユーザーが決めたいのは最終的な解像度である。
またファイルサイズは画素数で正規化しないと大小を判断できない。

## 決定

一括変換に「固定最適化」と「自動最適化」の2モードを設ける。
固定最適化は従来の設定（拡大率・最適化種別・品質スライダー）をそのまま使う。

自動最適化では、次の3つを選択させる。

- コンテンツ種別: アニメ / 実写
- 目標サイズ: 2K (1920px) / 4K (3840px) / 5K (5120px) / 8K (7680px)
- 画質プリセット: 画質最優先 (90) / 画質優先 (80) / 速度優先 (60) / 速度最優先 (40)

### 解像度の決め方

長辺だけを比較し、画像ごとに次の計画を立てる。

- 元の長辺が目標以上: 拡大しない（縮小もしない）。
- 拡大率が1.2未満: 超解像を使わず、高品質リサイズで目標長辺に合わせる。
  2倍のコストに見合う画質差が出ないため。
- 拡大率が1.2以上4以下: `ceil(拡大率)` 倍で超解像し、目標を超えた分は目標長辺へ縮小する。
- 拡大率が4を超える: 4倍で止める。2回アップスケールしても情報は増えないため。

縮小は目標を超えた出力だけに行い、アスペクト比は維持する。

### 圧縮品質の決め方

プリセットの品質を起点に、入力のBPP（ファイルサイズ ÷ 幅 ÷ 高さ）で補正する。

| 入力BPP | 補正 |
|---|---|
| 0.50以上 | -15 |
| 0.25以上0.50未満 | -10 |
| 0.12以上0.25未満 | 0 |
| 0.12未満 | +5 |

ファイルサイズが画素数に対して大きい画像は強く、既に小さい画像は弱く圧縮する。
補正はプリセットの範囲内（-15〜+5）に収め、プリセット間の逆転を防ぐ。

### 実行方式

- 変換前に全ファイルの寸法とファイルサイズを読み、`FilePlan`（倍率・縮小先・品質）を作る。
- アップスケールは1プロセス1倍率のため、倍率と縮小先が同じファイルだけを同じバッチにまとめる。
- 拡大しないファイルは超解像を通さず、リサイズ（必要な場合のみ）して圧縮キューへ流す。
- Real-CUGANは倍率に合うモデルをカタログから選ぶ。
- 自動モードの圧縮は `-q` を効かせるため、固定モードが使う `cq-level` / `crf` の上書きを渡さない。
- JPEG / PNG もプリセットの品質を反映する。

## 代替案

- 目標サイズを「1つ上のランク」に丸める
  - 却下: 5K選択でも6Kや8Kへ拡大され、最初の課題（過剰な拡大）が再発する。
    目標ちょうどへ縮小すれば足りる。
- 常に超解像モデルを使う
  - 却下: 1.2倍程度の拡大に2倍処理を行うと、中間画像だけが巨大になり画質差も小さい。
- エンコード結果を見ながら品質を探索する
  - 保留: ファイルサイズをより正確に合わせられるが、エンコード回数が増え、
    ステージ別ワーカーのスループット前提が変わる。初版はBPP補正で近似する。

## 結果

- 大きい画像は拡大されず、小さい画像は目標まで引き上げられる。
- 画像ごとに品質が変わるため、自動モードは固定モードより所要時間が読みにくい。
  拡大を省略した場合は固定モードより速くなることもある。
- 一括変換画面ではモードをタブで切り替え、タブ直下の「拡大」「圧縮」が
  そのモードの対象であることを示す。
- 品質値の実測チューニング（ADR 0040）はプリセット基準で取り直す必要がある。
- 実装箇所: `ConversionPlanner`、`ConvertOrchestrator`、`CompressionService`、`ConvertViewModel`、`ConvertView`。
