# アプリ更新をRex風のダウンロード・再起動フローにする

## ステータス

- 承認済み (Accepted)

## 背景・課題

ADR 0030 と ADR 0050 の更新カードは、更新ありの表示からインストール確認ダイアログを開き、
配置が終わると自動で新しいアプリを起動して終了していた。ユーザーはインストールを選んだ後、
完了を待つしかなかった。カードには進捗も再起動ボタンも無かった。

Superlogical Rex のターミナルアプリケーションの更新フローに合わせ、更新確認から再起動までを
サイドナビの更新カードだけで完結させる。

## 決定

- 更新ありカードを青背景にし、`アップデートがあります` と `ダウンロード` ボタンを表示する。
  ボタンからインストールを直接開始し、アプリ本体のインストール確認ダイアログは廃止する。
- ダウンロード中も青背景のまま、`ダウンロード中... n%` と確定バーを表示する。
  進捗は受信バイト数に基づき、1%単位で更新する。総バイト数が不明な場合は
  `ダウンロード中...` と不確定バーにフォールバックする（ADR 0050）。
- 検証・展開・ステージングも同じ青背景で段階名を表示し、失敗時は従来どおり赤背景と `再実行` ボタンを出す。
- ステージングが完了したら自動再起動せず、緑背景の `アップデート完了` カードへ切り替える。
  カード内の `アプリ再起動する` ボタンで、新しいアプリを `/Applications` へ配置して別プロセスから起動し、
  旧プロセスを終了する。配置に失敗した場合は赤い失敗カードへ切り替える。起動だけに失敗した場合は
  緑カードを残し、再ダウンロードせず起動を再試行できるようにする。
- 再起動までは新しいアプリをユーザーの Application Support に保持する。実行中のバンドルを
  先にゴミ箱へ移動すると、待機中に `Bundle.main` から資源を読めなくなるため。
- ステージング済みアプリは次回起動時に掃除する。再起動直後ではなく次回起動時とし、起動処理を優先して不要なコピーの削除を後回しにする。
- インストール中・再起動待ち・再起動中は、手動の更新確認を無効化する。
  確認中にインストールへ進んだ場合は、遅れて届いた確認結果で進捗や完了カードを上書きしない。
- ツール更新の確認ダイアログ・進捗・失敗時の挙動は変更しない。
- 青・緑の背景色も既存方針どおり Liquid Glass の tint で重ね、ライト・ダークモードで文字を読める
  前景色を選ぶ。青は状態を明確に見せるため tint 0.8、緑は黒文字のコントラストを保つため tint 0.65 とし、
  ADR 0030 の半透明tint方針を維持しつつ状態色だけを意図的に強める。

## 代替案

- インストール確認ダイアログを残す
  - 却下: Download ボタンから再起動までをカード内で完結できず、Rex のフローと異なるため。
- 配置後に自動再起動する（ADR 0050 の方針）
  - 却下: 緑色の完了カードと再起動ボタンを表示する時間がなくなるため。
- アクセントカラーを使い続ける
  - 却下: 青・緑で状態を表すという指定に合わず、色の変化が分かりにくいため。
- 再起動前に実行中のバンドルを置換する
  - 却下: 緑カードの待機中に `Bundle.main` の資源を読めなくなり、About画面や文言表示に影響するため。

## 結果

- 更新確認 → 青い Download カード → 青い進捗カード → 緑の再起動カードという流れになる。
- 実装箇所: `Core/UpdateCheckController.swift`、`App/RootView.swift`、`Core/GlassCard.swift`、
  `Services/UpdateService.swift`、`Services/AppPaths.swift`、`Features/About/AboutView.swift`、
  `Resources/Localizable.xcstrings`。
- テスト: 更新・ダウンロード・再起動の文言と進捗書式、再起動用ステージングを日英で検証する。
