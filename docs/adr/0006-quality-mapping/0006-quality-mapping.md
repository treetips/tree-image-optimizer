# 品質スライダーと最適化種別のパラメータ適用

## ステータス

- 承認済み (Accepted)

## 背景・課題

`convert.md` では「品質」スライダー（最小 `1`・最大 `100`・初期値 `80`）が定義されている。
一方 `compression.md` では「最適化種別」ごとに固定の圧縮パラメータ（JPEG XL の `--distance`/`-e`/`--lossless_jpeg`、AV1 の `--speed`/`-q`/`-y`/`-a`）が定義されており、
品質スライダーと最適化種別のパラメータがどう関連するかが曖昧だった。

## 決定

品質スライダーと最適化種別の役割を以下のように分離する。

- **品質スライダー**: 品質（劣化の許容度）を制御する主軸。
  - JPEG XL: `--distance` に変換して適用する。`100` はロスレス相当（距離 `0`）、`80` は視覚的にほぼロスレス相当（約 `1.0`）。変換式は `distance = (100 - quality) * 0.1`。
  - AV1: `-q` にそのまま適用する。
- **最適化種別**: コンテンツ傾向に応じた固定パラメータを提供する。
  - JPEG XL: `-e`（effort）と `--lossless_jpeg=0`。ただし `画質優先` の effort は仕様の範囲（1〜10）を超えているため `9` に丸める。
  - AV1: `--speed`・`-y`（yuv）・`-a`（aom オプション）。

`compression.md` の最適化種別ごとの表（distance/quality）は品質スライダーの初期値として扱うものではなく、
種別固有のエンコーダオプションとして実装する。

## 代替案

- 品質スライダーを無視して最適化種別の固定パラメータのみを使う
  - 却下: 品質スライダーのUIが無意味になるため。
- 最適化種別の表に品質スライダーをそのままマージする
  - 却下: 表が2つの品質概念を持ち、曖昧さが残るため。

## 結果

- 品質スライダーが意味を持ち、最適化種別はコンテンツ傾向に応じたパラメータを提供する。
- 実装箇所: `lib/data/services/compression_service.dart`
