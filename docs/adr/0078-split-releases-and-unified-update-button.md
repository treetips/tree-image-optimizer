# アプリとツールのReleaseを分離し更新ボタンを統合する

## ステータス

- 承認済み (Accepted)
- 更新通知の見た目と操作配置は [ADR 0079](./0079-rex-style-update-pill.md) で置換

## 背景・課題

ADR 0064でアプリ本体とツールの更新処理は分離したが、配布物は同じ `vX.Y.Z` Releaseに置かれ、双方とも `releases/latest` を参照していた。このため、ツールだけを更新する際もアプリのバージョンを上げる必要があり、GitHubの最新リリースという1つのチャネルで両方を扱っていた。

ヘッダーにはアプリ更新とツール更新のカードが並び、更新ボタンも2個になる。両方に更新がある場合、利用者はどちらを先に更新するかを選ぶ必要があった。

## 決定

### Releaseの分離

- アプリ本体は `vMajor.Minor.Patch` の通常リリースとして公開し、GitHubの「Latest」を占める。
- ツールは `tools-latest` の事前リリースとして公開する。アプリのバージョンやタグは変更しない。
- アプリReleaseの成果物はアプリZIP、`update-info.json`、アプリ用の `SHA256SUMS.txt` に限定する。
- ツールReleaseの成果物は `tools-info.json`、ツール単位ZIP、ツール用の `SHA256SUMS.txt` に限定する。
- ツールの取得先は `releases/download/tools-latest/` で統一する。アプリは `releases/latest/download/update-info.json` を引き続き使う。
- ツールReleaseを事前リリースに保つことで、アプリの「Latest」を隠さない。公開処理でも事前リリースを明示する。
- アプリ・ツールとも、全資産をアップロードして内容とチェックサムを検証してからDraftを公開する。失敗時は利用者へ壊れた配布物を露出しない。
- アプリRelease作成前に `tools-latest/tools-info.json` の取得を検証する。ツール配布が無いままアプリを公開しない。
- 既存クライアントはアプリの更新を継続できる。新しいアプリへ更新するまではツールの更新確認だけ失敗し、既存ツールを使い続ける。

### 初回ツール準備

- 初回起動でツールが不足している場合は、まず開発用ローカルコピーからの修復を試す。
- ローカルコピーが使えない場合は、`tools-latest/tools-info.json` を使い、不足する全ツールをSHA-256検証付きで取得する。
- ツール更新の確認はツール準備が完了してから開始する。不足準備と日常の更新確認を同時に動かさない。

### 更新ボタン

- ヘッダー右端に表示する更新ボタンは1個だけにする。
- 更新ありの文言は次の3種類に限定する。

| 更新の状態 | ボタン文言                       |
| ---------- | -------------------------------- |
| 両方あり   | `アプリとツールの更新があります` |
| アプリのみ | `アプリの更新があります`         |
| ツールのみ | `ツールの更新があります`         |

- ボタンのクリックで確認ダイアログを挟まず、利用可能な更新を開始する。
- 両方ある場合はツールを更新してからアプリのダウンロード・ステージングを行う。ツールの更新に失敗した場合はアプリ更新を開始しない。
- ツールだけの更新ではアプリを再起動しない。アプリを含む更新は従来どおり緑色の完了カードから再起動する（ADR 0076）。
- インストール中・再起動待ち・失敗時もヘッダーに表示する更新操作は1個に統合する。失敗時の再実行は、未完了の更新を同じ順序で実行する。
- 変換の実行中は更新を開始しない。ツール更新中は新しい変換を受け付けず、配置の置換が終わってから再開する。

## 代替案

- アプリとツールを同じReleaseに残す
  - 却下: ツールだけの配布にアプリのバージョンとタグが必要になり、更新頻度の違いを吸収できない。
- ツールReleaseを通常リリースにする
  - 却下: GitHubの「Latest」がアプリでなくなり、既存の更新情報取得経路を壊す。
- 更新ボタンを2個のままにする
  - 却下: 利用者に更新順序を委ねることになり、今回の表示・操作要件を満たさない。
- 両方の更新を並列実行する
  - 却下: アプリの再起動でツール更新が中断される可能性がある。ツールを先に完了させてからアプリを準備する方が安全。

## 結果

- ツールだけをアプリのバージョン変更なしで配布できる。
- GitHubの「Latest」はアプリ本体のままで、アプリとツールは別々のRelease URLを参照する。
- クリーンインストールでも `tools-latest` から全ツールを準備できる。
- ヘッダーの更新ボタンは更新対象に応じた1つの文言と操作にまとまる。
- 本ADRはADR 0077を置き換える。ADR 0064のうち、同じReleaseへのツール同梱とツール確認ダイアログに関する部分も本ADRへ置き換える。
