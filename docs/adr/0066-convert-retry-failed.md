# 一括変換で失敗したファイルだけを再実行できるようにする

## ステータス

- 承認済み (Accepted)

## 背景・課題

一括変換は数千件を処理することがある。数件だけ失敗した場合、修正して再実行する手段は
「最初から全件をやり直す」しかなく、既に成功したファイルまで再度変換されて時間が無駄だった。

結果表（`ConvertJobStore.rows`）はファイルごとにアップスケール/圧縮/出力の成否を保持しており、
「失敗した行」を特定する情報は既に揃っている。これを再実行の対象にできれば、
成功済みファイルを巻き込まずに済む。

## 決定

結果表から失敗したファイルだけを抽出し、同じ設定・同じ出力先で再実行するボタンを設ける。

### 再実行の対象

- `FileRow` の「失敗」判定（`ConvertJobStore.isFailure`）に一致する行を対象にする。
  途中の段階（アップスケール/圧縮）で失敗した行も含む。
- キャンセルされた行は対象にしない。キャンセルは「失敗」ではなく中断であり、
  再実行の意味（失敗の修正）とは別の操作として扱う。

### 実装

- `ConvertJobStore` に直近の実行で使った `ConvertConfig` と出力先を保持し、再実行で再利用する。
- 再実行は成功済みの行を残したまま、失敗行だけを「待機中」に戻し、その行インデックスと
  入力ファイルだけをオーケストレータへ渡す。オーケストレータの `FileOutcome.index` は
  渡したファイル配列内の位置なので、`indexMap`（ファイルindex→行index）で元の行へ写像する。
- 件数と進捗率は行の状態から再集計する。再実行開始時点で失敗行ぶんを除外して
  一旦 `recount()` し、以降は1件完了ごとに通常どおり加算する。
- 再実行ボタンは「実行中でなく、失敗行が1件以上ある」ときにだけ表示する。

### 完了時の集計

完了時はオーケストレータが返す「再実行した件数」ではなく、行の状態から全体を `recount()` する。
再実行は表の一部だけを更新するため、部分件数をそのまま全体件数へ当てると
成功済み行の件数が失われる。

## 代替案

- **全件を最初からやり直す（現状）**: 成功済みも再変換され、時間と無駄な上書きが発生する。却下。
- **再実行時だけ表を作り直す（失敗行のみの新規実行）**: 実装は単純だが、成功済みファイルの
  文脈（「100件中97件成功」）が消える。部分再実行のほうが利用者にとって自然なため採らない。
- **失敗行のステータスだけを手動で戻して再度「実行」する**: 利用者に手作業を強いるうえ、
  どの行を戻したかの把握が難しい。却下。

## 結果

- 失敗したファイルだけを最小の操作で再処理でき、成功済みファイルの再変換を避けられる。
- 再実行中も一時停止・キャンセルが機能する（既存の `RunControl` を再利用する）。
- 表の成功行は維持され、フッターの成功・失敗・削減の集計も再実行後の状態を反映する。
- 実装箇所: `ConvertJobStore.swift`、`ConvertView.swift`、`Localizable.xcstrings`。
