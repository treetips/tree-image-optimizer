# 一括変換を一時停止・キャンセルできるようにする

## ステータス

- 承認済み (Accepted)

## 背景・課題

一括変換は開始すると最後まで止められず、実行中は実行ボタンが非活性になるだけだった。
対象フォルダや画質設定を選び直したい、誤って開始したので止めたい、といった場面でも、
アプリを終了する以外に中断する手段が無かった。

変換は upscayl・Real-CUGAN・libjxl・avifenc を外部プロセスとして動かしている。
そのためSwiftのタスクをキャンセルしただけでは子プロセスは最後まで走り、止めたように見えない。

一方で、一時停止を「プロセスを即座に強制終了する」方式にすると、処理中の4ファイル分の
超解像結果が捨てになり、再開時に同じバッチをやり直す必要がある。

## 決定

- 一時停止は区切りで止める。`BatchScheduler` と `UpscaledQueue` は停止中に新しい作業を
  配らず、実行中のプロセス（アップスケールは最大4ファイル、圧縮は1ファイル）が
  完了してから待機する。
- 再開は停止前のスケジューラ・キューの状態をそのまま使う。進捗と処理枠は保持する。
- キャンセルは `RunControl` を経由して全ワーカーへ伝え、`ProcessRunner` が実行中の
  子プロセスへSIGTERMを送る。3秒以内に終わらない場合はSIGKILLを送る。
- キャンセルで途中終了した段階は一覧表に「キャンセル」と表示する。完了済みの段階
  （成功・失敗）と、それまでに出力先へ確定したファイルは残す。
- 一時停止・キャンセルの状態は `ConvertJobStore` が持ち、画面を切り替えても維持する。
- かんたん変換には入れない。一括変換だけに置く。

## 代替案

- 一時停止でプロセスを即時終了する（強制停止）
  - 却下: 処理中のバッチが無駄になり、再開時に同じファイルをやり直すことになる。
- キャンセルでSwiftのタスクだけをキャンセルする
  - 却下: 子プロセスが残り、CPUとGPUを使い続ける。画面は止まったように見えて実際は動く。
- かんたん変換にも同じ操作を入れる
  - 却下: 「フォルダへドロップして実行」という単純な操作に、停止系の判断が増える。
    かんたん変換は設定も少なく、中断したい場合はウインドウを閉じれば足りる。

## 結果

- 一時停止の反映は、1バッチ（最大4ファイル）と実行中の圧縮1件が終わるまで遅れる。
  処理の重いフォルダでは数十秒かかることがある。
- キャンセルはSIGKILLの猶予を含めても数秒以内に止まる。
- 出力先へ確定済みのファイルは残る。圧縮・出力の途中で止めたファイルは
  一時ディレクトリごと削除し、中途半端な出力を出力先へ残さない。
- 実装箇所: `Services/BatchScheduling.swift`（`RunControl`）、`Services/ProcessRunner.swift`、
  `Services/ConvertOrchestrator.swift`、`Features/Convert/ConvertJobStore.swift`、
  `Features/Convert/ConvertView.swift`。
  テスト: `TreeImageOptimizerTests/ConvertPauseCancelTests.swift`、`ProcessRunnerTests.swift`。
