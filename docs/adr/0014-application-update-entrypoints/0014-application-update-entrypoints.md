# アプリケーション更新確認の起動経路

## ステータス

- 代替済み (Superseded) — [ADR 0015](../0015-desktop-updater-migration/0015-desktop-updater-migration.md) で
  `auto_updater` → `desktop_updater` への移行に伴い置き換え。起動経路 (メニュー/起動時/About) の
  3経路方針は0015でも継承される。

## 背景・課題

- 更新確認の仕様として、macOSメニューバー、アプリケーション起動時、About画面の3経路が必要になった。
- 更新サーバーや配布用フィードの設定は未完了であり、更新処理自体は失敗する可能性がある。

## 決定

- 既存の `AboutViewModel.checkForUpdates` を更新確認の共通エントリーポイントとして利用する。
- macOSのアプリケーションメニュー `tree_image_optimizer` に `アップデートを確認` を追加し、同じビューモデルを呼び出す。
- `main` でアプリケーション起動後に更新確認を非同期で開始する。
- 更新確認の失敗は既存の `UpdateAlertType.failure` と失敗メッセージで処理し、起動や画面操作を妨げない。
- 更新フィードが未設定のため、現時点では更新処理が失敗することを許容する。

## 代替案

- About画面からの更新確認だけを維持する
  - 却下: 起動時とmacOSメニューバーからの更新確認要件を満たせないため。
- 更新確認の処理を各画面・メニューに個別実装する
  - 却下: 状態表示と失敗処理が分散し、結果の一貫性を保てないため。

## 結果

- About画面、起動時、macOSメニューバーから同じ更新確認処理を実行できる。
- 実際の更新フィード設定と更新成功フローは別途対応する。
