# 更新通知をRex風のステータスピルにする

## ステータス

- 承認済み (Accepted)

## 背景・課題

更新通知を macOS のツールバーへ置くと、カスタムビューが極端に圧縮され、ラベルや操作ボタンが消えてアイコンだけになる場合があった。従来は更新ありのラベル自体が操作ボタンで、閉じる操作もなかった。

Superlogical Rex の更新通知は、必要な本文と操作を固有サイズのカプセル内に収め、状態アイコン・操作ボタン・閉じるボタンを明確に分けている。

## 決定

- 更新通知はヘッダー下の右上へ配置し、ツールバーの圧縮に任せず固有サイズのカプセルとして表示する。`Spacer` で全幅化しない。
- 左端に円形背景の状態アイコン、中央にステータス本文、右端に操作ピルと円形の閉じるボタンを置く。
- 更新ありは本文クリックではなく、`ダウンロード` / `インストール` の操作ピルから開始する。
- 更新なし・更新あり・失敗時は閉じるボタンで通知を消せる。実行中と再起動待ちは、進捗や再起動操作を失わないよう閉じるボタンを表示しない。
- ダウンロード中は円形の進捗表示と右端の百分率を使う。
- Liquid Glass の tint は半透明とし、Rexの青・緑・ニュートラルに近い視覚強度にする。

## 代替案

- ツールバーの圧縮に任せる
  - 却下: ウィンドウ幅やツールバー項目によって本文・操作部が消えるため。
- 更新ありのラベル全体を操作ボタンのままにする
  - 却下: Rexのように本文・操作・閉じるを区別できず、誤操作も増えるため。
- 更新通知をモーダルやサイドナビへ戻す
  - 却下: ヘッダーで状態を確認し、同じ場所で操作するRexの体験と異なるため。

## 結果

- 更新通知はウィンドウ幅が変わっても本文と操作部を維持する。
- 状態アイコン・操作ピル・閉じるボタンが重ならず、Rexに近い外観になる。
- 本ADRは ADR 0076・ADR 0078 の更新通知UIに関する部分を置き換える。更新の実行順序とRelease分離は変更しない。
