# コールアウトを見出しクリックで開閉できるパネルにする

## ステータス

- 承認済み (Accepted)

## 背景・課題

一括画像変換画面は縦に長く、「対応フォーマット」とモードの説明が常に展開されている。
設定を変えるたびに説明を読み直す必要はなく、画面をスクロールする手間になっていた。

モードの説明は「モードの特徴」という別の見出しで開閉していたため、直上の
「固定最適化 / 自動最適化」タブと見出しが二重になり、どちらが本文の見出しか分かりにくかった。

## 決定

- 「対応フォーマット」とモードの説明を、見出しクリックで開閉できるパネルにする。
  - 見出しの右に開閉状態を示すシェブロン（`chevron.up` / `chevron.down`）を置く。
  - 初期状態は展開。縮小中は見出しだけを残し、本文を隠す。
  - パネルをホバーするとポインターカーソルにし、ホバー中は枠を強めてクリックできることを示す。
- モードの説明はモード名（`固定最適化` / `自動最適化`）をそのまま見出しにし、
  「モードの特徴」ボタンは削除する。モードを切り替えるタブは従来どおり残す。
- 開閉状態は `settings.json` の `batchConvert` に保存し、次回起動時に復元する
  （`formatsExpanded` / `modeNoteExpanded`）。キーが無い旧形式は展開を既定にする。
- 開閉の見た目と操作は `CollapsibleCallout` に集約し、`CalloutContainer` の装飾を再利用する。
- かんたん変換画面の「対応フォーマット」は、操作を絞るため常時表示のままにする。

## 代替案

- SwiftUI の `DisclosureGroup` を使う
  - 却下: ガラスカード上のコールアウト装飾を保ったまま、見出しのシェブロンだけを
    差し替えられない。
- かんたん変換画面の「対応フォーマット」も開閉式にする
  - 却下: かんたん変換は設定項目が少なく、対応形式を常に見せておく方が迷わない。
- 開閉状態を保存しない
  - 却下: 一度縮小すると画面を開き直すたびに展開へ戻り、同じ操作を繰り返すことになる。

## 結果

- 説明を読まないときはパネルを縮小でき、設定項目までスクロールしやすくなる。
- 「モードの特徴」という別見出しがなくなり、モード名と本文の対応が分かりやすくなる。
- 開閉状態は次回起動時にも引き継がれる。
- 実装箇所: `CollapsibleCallout`、`SupportedFormatsCallout`、`ConvertSettingsView`、
  `ConvertView`、`ConvertViewModel`、`SettingsStore`。
