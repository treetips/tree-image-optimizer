# Release Toolsを日本時間で定期実行する

## ステータス

- 承認済み (Accepted)

## 背景・課題

ADR 0080により、Release Toolsは上流の最新バージョンを検出し、更新がなければ配布物を変更せず正常終了できるようになった。しかし、実行は手動に限定されており、上流更新を継続的に反映するには運用担当者が実行ボタンを押す必要があった。

ツールはアプリ本体とは独立して更新されるため、アプリのリリースを待たずに上流更新を反映したい。

## 決定

- Release ToolsをGitHub Actionsの`schedule`トリガーで定期実行する。
- 実行頻度は月・水・金の日本時間00:00とし、`cron: '0 0 * * 1,3,5'`と`timezone: 'Asia/Tokyo'`を指定する。
- 初回配布や修正時の再実行に備え、`workflow_dispatch`も維持する。
- 定期実行では`force`を使わず、上流更新がある場合だけ配布物を更新する。
- スケジュール実行はデフォルトブランチの最新コミットを使い、デフォルトブランチは`main`を前提とする。

## 結果

- 上流更新は次回の定期実行で検出され、アプリのバージョンを変えずにツール配布物へ反映される。
- 更新がない実行はGitHub Releaseを変更せず成功として終了するため、定期実行の運用負荷が小さい。
- 初回や公開済みassetの修復は、従来どおり手動実行で対応できる。
- GitHub Actionsの高負荷時には実行が遅れることを許容する。

## 代替案

- UTCのcronで指定する: 日本時間との日付ずれを運用手順で管理する必要があるため不採用。
- 外部のcronサービスから実行する: GitHub標準機能だけで完結せず、認証情報や外部サービスの運用が増えるため不採用。
- 毎日実行する: 指定された運用頻度を超え、不要なランナー実行が増えるため不採用。
