# AVIFの速度プリセットとクオリティ指定を実測で詰める

## ステータス

- 承認済み (Accepted)

## 背景・課題

「AVIFで圧縮するとJPEG XLより遥かに遅い」という状況を、アプリの実設定
（並列数6 → エンコーダ1プロセス1スレッド、品質80）で実測した。

| 種別 | エンコーダ | 設定 | 1536x2752 | 3072x5504 | JPEG XL比 |
|---|---|---|---|---|---|
| 実写・写真 | SVT-AV1 | speed4 / crf11 | 0.67s | 2.12s | 速い |
| 速度優先 | SVT-AV1 | speed8 | 0.12s | - | 速い |
| アニメ・イラスト | libaom | speed3 / 444 / cq20 | 5.53s | 33.4s | **遅い** |
| 画質最優先 | libaom | speed4 / 444 / cq16 | 3.21s | - | **遅い** |
| JPEG XL（比較） | libjxl | effort7 / distance2.0 | 1.50s | 5.62s | 基準 |

時間は実写画像 `1536x2752`、および同画像を2倍に拡大した `3072x5504` で測定。
イラスト（1500x1641、アルファ有り）ではアニメ設定が5.53s、JPEG XLが1.05sだった。

遅さは libaom を使う2種別に集中していた。原因は `--speed`（libaomの `cpu-used`、
libavifが0..9にclamp）で、3〜4がJPEG XLの effort7 の約3〜6倍遅い。

速度プリセットを上げたときの実測（イラスト1500x1641、白背景合成で画質測定）:

| 設定 | 時間 | サイズ | VMAF |
|---|---:|---:|---:|
| aom speed3 cq20（変更前） | 5.53s | 113,065 | 96.50 |
| aom speed5 cq20 | 2.35s | 115,991 | 96.47 |
| aom speed6 cq20 | 0.35s | 123,994 | 96.51 |
| aom speed6 cq22 | 0.36s | 117,179 | 96.47 |
| aom speed8 cq20 | 0.17s | 132,357 | 96.54 |
| JPEG XL effort7 | 1.05s | 144,836 | 95.78 |

`--speed` は VMAF をほぼ変えず、PSNRのみ約1dB下がる（誤差の分布が変わる）。
遅さの内訳は、速度プリセットが支配的で、444は約19%、アルファは約13%。

## 決定

- **libaomの `--speed` は据え置く**（アニメ3、画質最優先4）。
  画質を優先するため。結果としてAVIFはJPEG XLより遅いまま（アニメは約5.9倍遅い）。
  速度で不満が出た場合は `speed6` で約15倍高速化できることを記録しておく。
- サイズ増を抑えるため、libaomの `cq-level` を一段上げる。
  - アニメ・イラスト: `20` → `22`（サイズ +9.7% → +3.6%、VMAF 96.51→96.47）
  - 画質最優先: `16` → `18`
- SVT-AV1を使う実写・写真の `--speed` を `4` → `6` にする。
  - 0.67s → 0.23s（2.9倍）。4倍拡大画像では2.12s → 0.71s。
- あわせて実写の `crf` を `11` → `12` にしてサイズ増を抑える。
  - 1536x2752 で 113KB → 116KB（+3.3%）、VMAF 95.41 → 95.38、速度2.9倍。
- 速度優先（SVT speed8）は変更しない。

## 代替案

- libaomを `speed6` まで上げる
  - 却下: VMAFは不変だがPSNRが約1dB下がり、サイズが6〜10%増える。
    画質優先の2種別では速度より画質を取る方針。
- libaomを `speed8` まで上げる
  - 却下: 速度は32倍になるが、4倍拡大画像ではJPEG XLより31%大きくなる。
- YUV 444 を 420 にする
  - 却下: 速度効果は約1.2倍にとどまり、画質仕様が変わる（ADR 0037で却下済み）。
- libaom 3.14.1 → 3.15.3 へ更新する
  - 却下: 同条件で 5.53s → 6.19s と逆に遅い。更新は速度向上にならない。
- スレッド数を増やす
  - 却下: エンコーダの総スレッド数は並列数ぶんに固定されており（ADR 0039）、
    1プロセスのスレッドを増やすとプロセス数が減るだけで総スループットは変わらない。
    少数ファイル時のみ `min(並列数, ファイル数)` で自動的に1プロセスあたりが増え、
    その場合も予算ぶんのスレッドが当たる。

## 結果

- 実写・写真と速度優先はJPEG XLより速く、実写は2.9倍高速化した。
- アニメ・イラストと画質最優先は画質優先のため据え置きで、
  アニメ設定（`speed3` / 444）ではJPEG XLの約5.9倍遅い
  （`3072x5504` 実写画像で33.4s、JPEG XLは5.62s）。
  同画像で `speed6` にすれば2.29s（JPEG XL比2.5倍速い）になることを確認済みで、
  方針変更時に使える。
- 品質スライダー（`-q`）はアニメ・実写・画質最優先では `cq-level` / `crf` が
  固定値のため効かない（速度優先のみ `-q` が効く）。本ADRの対象外で、未修正。
- アルファ付き画像は透過領域のRGBが再録で変わるため、素朴なVMAF比較では
  他コーデックが異常に低く出る。画質は白背景で合成してから測定した。
- 単体テスト: `ConvertPipelineTests.avifencArgs`（引数の変更を反映）。
- 実装箇所:
  - `TreeImageOptimizer/TreeImageOptimizer/Services/CompressionService.swift`
