# 比較プレビューの表示でレイアウトの再計算ループを起こさない

## ステータス

- 承認済み (Accepted)

## 背景・課題

一括変換の結果表から変換前後の比較プレビューを開くと、アプリがクラッシュしていた。
クラッシュレポートでは AppKit の `_postWindowNeedsUpdateConstraints` が
「Update Constraints in Window」の上限を超えて例外を投げていた。

原因は `Table` の行高の再計算と、プレビューセルのレイアウト更新が連鎖していたこと。
`Table` はセルの中身の理想サイズから行高を決めるため、ホバー時の拡大アニメーションや
結果表の高さの変化が制約更新を再入させ、ウィンドウの制約更新回数が上限に達していた。

## 決定

- 比較プレビューのセルは理想サイズを固定する。
  - アイコンを `18x18` の固定フレームに収め、ホバー時の拡大アニメーションと
    `pointerStyle`、ツールチップ、フォーカス移動を削除する。有効・無効は色だけで示す。
  - `Button` ではなく固定サイズの画像とタップジェスチャにし、押下状態とフォーカスが
    行のレイアウト更新を起こさないようにする。読み上げ用のボタン特性とアクションは残す。
- 結果表の高さを `360` に固定し、行高の更新で `Table` 自体の高さが変わらないようにする。
- 比較ウインドウはボタンアクションの同じ更新サイクルでは開かず、次のメインアクター
  ジョブで開く。
- 比較ウインドウは生成時に `styleMask` を指定し、コンテンツ設定後の変更を避ける。
  ウィンドウは表示前に保持して、表示直後のレイアウト中に解放されないようにする。
- `ComparisonWindowController` は `@MainActor` で隔離し、ウィンドウ辞書の更新と
  ウィンドウ生成をメインアクター上で行うことを型で保証する。

## 代替案

- ホバー演出を残したまま、比較ウインドウの生成だけを遅らせる
  - 却下: 行高の再計算はセルの理想サイズの変化で起きるため、演出を残すと同じループを
    誘発しうる。
- 比較を `sheet` で表示する
  - 却下: 壁紙サイズの画像を小さい領域へ縮小すると、アップスケール後のジャギーが
    目立つ（ADR 0071）。
- 例外を捕捉して処理を続ける
  - 却下: AppKit の制約更新ループはプロセスを安全に継続できる状態ではなく、
    例外を握りつぶすと描画が壊れたまま残る。

## 結果

- 結果表から比較プレビューを開いても、制約更新のループでクラッシュしない。
- 行高と結果表の高さが安定し、変換中に行が増えてもレイアウトが揺れない。
- 実装箇所: `Features/Convert/BeforeAfterPreviewView.swift`、`Features/Convert/ConvertView.swift`。
