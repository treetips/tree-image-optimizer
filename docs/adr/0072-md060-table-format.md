# Markdownの表をrumdlのMD060で桁揃えする

## ステータス

- 承認済み (Accepted)

## 背景・課題

rumdl導入時（[ADR 0043](0043-markdown-rumdl-ci.md)）は既定で有効なルールだけを使っていた。
表の桁揃えを行う MD060 は既定で無効なopt-inルールのため、表のセル幅が揃っていない
Markdownがそのまま残り、`rumdl fmt` を実行しても表は整形されなかった。

## 決定

- `.rumdl.toml` の `[global]` に `extend-enable = ["MD060"]` を追加し、MD060 を有効にする。
- `[MD060]` で `style = "aligned"` を指定し、列幅を空白で揃える。
- `max-width = 0`（MD013が無効なので実質無制限）にし、幅の広い表でも自動で
  compact に落ちて桁揃えが崩れないようにする。
- 既存の表は `rumdl fmt --fixable MD060` で一括整形する。

## 代替案

- `style = "any"` のまま有効化する
  - 却下: 既定値の `any` は既存の書式を尊重するだけで、崩れた表は整形されない。
    有効化しても目的（表が整形される）を満たさない。
- `style = "compact"` または `"tight"`
  - 却下: 日本語の表はセル幅が広く、区切りの空白を詰めると列の境界が読みにくい。
- MD013（行長）を有効にして自動compactに任せる
  - 却下: 日本語の表は行長を超えやすく、表ごとにcompactとalignedが混在して
    かえって不揃いになる。
- MD060を有効にせず手作業で揃える
  - 却下: セル幅は文字数ではなく表示幅で決まり、CJKを含む表を手で揃え続けるのは現実的でない。

## 結果

- 表のセル幅と区切り行が揃い、レビュー時の差分が読みやすくなる。
- CIの `rumdl fmt --check` が表の崩れを検出するため、崩れた表は混入しない。
- CJKの表示幅はMD060がEast Asian Widthで計算するため、日本語の表でも桁が揃う。
- 実装箇所: `.rumdl.toml`。
- 既存の表は20ファイル・419行を整形した。差分は空白と区切り行のダッシュだけで、
  表の内容は変わらない。
- CIが固定しているrumdl 0.3.2でも同じ設定で整形・検査できることを確認済み。
