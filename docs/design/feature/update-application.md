# アプリケーションの更新

## 更新の条件

- `Info.plist` の `CFBundleShortVersionString`（バージョン）と `CFBundleVersion`
  （ビルド番号）を、公開先の `update-info.json` が示す最新リリースと比較する。

- 比較は更新情報のバージョン比較で行い、セマンティックバージョンを先に比べ、
  同じ場合にビルド番号を比べる。

- `update-info.json` は GitHub Releases の latest から取得する。

  ```text
  https://github.com/treetips/tree-image-optimizer/releases/latest/download/update-info.json
  ```

  取得先URLはアプリ内の定数で定義する。

## 仕組み

- 更新処理と更新確認の状態管理はアプリ内で完結する。外部のアップデーターや
  別プロセスは使わない。

- Releaseワークフローがアプリ本体の `.zip` と一緒に `update-info.json` を公開する。

  ```json
  {
    "version": "0.3.0",
    "build": 3,
    "url": "https://github.com/treetips/tree-image-optimizer/releases/download/v0.3.0/Tree-Image-Optimizer-v0.3.0-macos.zip",
    "sha256": "<hex>"
  }
  ```

- `update-info.json` の取得は15秒でタイムアウトし、HTTP 200とJSONのデコードに
  成功した場合だけ比較する。

- ダウンロードしたZIPはSHA-256で改ざん・破損を検出する。署名検証は行わない。

## 更新確認の起動経路

- macOSメニューバーの `Tree Image Optimizer` → `更新を確認`
  - 手動チェック。更新なし・失敗時はダイアログで表示し、失敗時を除きサイドナビ下部の更新カードにも反映する。
  - 更新ありは確認ダイアログを開かず、サイドナビの青い更新カードに `ダウンロード` ボタンを表示する。
- アプリケーション起動時
  - バックグラウンドで自動チェック。ダイアログは表示せず、更新が見つかった場合は
    組み込み更新カードに反映される。
- About画面
  - `アップデートを確認` ボタン（手動チェック）。メニューバーと同じ挙動で、
    結果はメッセージとサイドナビ下部の更新カードに表示する。更新なし・失敗時はダイアログも表示する。
    確認失敗時は更新カードを変更しない（ネットワーク失敗で「更新なし」と表示するのは誤解を招くため）。

## インストールの流れ

1. 起動時または手動の更新チェックで、サイドナビ下部に青い `アップデートがあります` カードを表示する。
2. カード内の `ダウンロード` ボタンをクリックすると、そのままダウンロードを開始する。
3. ダウンロード中は青背景で `ダウンロード中... n%` と確定バーをリアルタイムに表示する。
   総バイト数が不明な場合は `ダウンロード中...` と不確定バーにする。
4. ダウンロード後は青背景のまま、検証・展開・再起動用のステージングを不確定バーで表示する。
5. 展開した `.app` をユーザーの Application Support 内へ移動し、緑背景の `アップデート完了` カードへ切り替える。アプリは自動終了しない。
6. `アプリ再起動する` ボタンをクリックすると、ステージングしたアプリを `/Applications/<アプリ名>.app` へ配置する。同名のアプリが既にあればゴミ箱へ移動してからコピーする。
7. 新しいバージョンを別プロセスで起動し、1秒後に旧プロセスを終了する。配置に失敗した場合は赤い `インストールに失敗` カードへ切り替える。起動だけに失敗した場合は緑カードを残し、再ダウンロードせず起動を再試行できるようにする。
8. 失敗した場合は赤い `インストールに失敗` カードに切り替わり、`再実行` で
   ダウンロードからやり直せる。

## 更新カード仕様

### 更新が有る場合

- 左サイドナビの下部に `アップデートがあります` と `ダウンロード` ボタンを表示。
- `ダウンロード` ボタンからそのままインストールを開始する。確認ダイアログは表示しない。
- 背景色は青。テキスト色はライトモード・ダークモードのどちらでも読める色にする。
- LiquidGlassで表示。

### インストール中の場合

- 左サイドナビの下部に青背景のカードを表示する。
- ダウンロード中は `ダウンロード中... 42%` と確定バーを表示する。総バイト数が不明な場合は
  `ダウンロード中...` と不確定バーにする。
- 検証・展開・ステージング中は `ダウンロードを検証中`・`展開中`・`アップデートを準備中` と
  不確定バーを表示する。
- カードはクリックできない。背景色・テキスト色は更新ありカードと同じ。
- 失敗時は背景を赤色にした `インストールに失敗` カードへ切り替える。
  - カード内に `再実行` ボタンを表示し、クリックするとダウンロードからやり直す。
  - 失敗の詳細理由はエラーダイアログとAbout画面のメッセージに表示する。
- インストール中は手動の更新確認を無効化する。

### 再起動待ちの場合

- ステージングが完了すると、緑背景の `アップデート完了` カードへ切り替える。
- カード内に `アプリ再起動する` ボタンを表示し、クリックで `/Applications` へ配置して新しいアプリを起動し、旧プロセスを終了する。
- 自動再起動はしない。配置に失敗した場合は赤い失敗カードへ切り替える。起動だけに失敗した場合は緑カードを残し、エラーダイアログを表示する。
- ステージング済みアプリは次回起動時に掃除する。
- 再起動待ち・再起動中は手動の更新確認を無効化する。

### 更新が無い場合

- 左サイドナビの下部に `アップデートは有りません` と表示。
- クリックすると、何もせず更新カードを非表示化。
- 更新カードは10秒後に自動的に非表示化。
- 更新カードの背景色は、透明で目立たない色で表示。
- 更新カードのテキスト色は、左サイドナビのメニュー項目と同様のテキスト色にする。
- LiquidGlassで表示。

## ツールの更新

アプリ本体とは別に、変換に使う外部ツールも更新する。仕組みと配布は
[ADR 0064](../../adr/0064-separate-tools-distribution/0064-separate-tools-distribution.md) を参照。

- 起動時に `tools-info.json` を GitHub Releases の latest から取得し、
  `tools/.installed.json` とバージョンを突き合わせる。
- 差分があるツールだけを `ツール更新が有ります` カードで通知する。
  カードはアプリ本体の更新カードの下に、独立した状態で表示する。
- カードをクリックすると確認ダイアログを表示し、更新対象のツール名を列挙する。
- 更新はツール単位のZIPをダウンロードし、SHA-256検証・展開・配置を行う。
  進捗はダウンロードの受信バイト数に基づく確定バー、検証・展開は不確定バーで表示する。
- 更新中は `インストール中` カードを表示し、変換画面の実行を抑止する。
  完了してもアプリの再起動は行わない。
- 失敗時は赤い `インストールに失敗` カードに切り替わり、`再実行` でやり直せる。
- アプリ本体の更新とツール更新は独立して動作し、同時に実行できる。

## 配布・設定

- アプリ側の定数として、更新情報の取得先URLと各ツールのバージョンを保持する。
  各ツールのバージョンはAbout画面と `tools/.installed.json` の初期値に使う。
- リリース設定は `.github/workflows/release.yml` が担う。
  - アプリZIPと `update-info.json`（`version` / `build` / `url` / `sha256`）を生成する。
  - `tools-info.json` とツール単位ZIP（`tools-<name>-<version>.zip`）を生成する。
