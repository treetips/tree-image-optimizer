# アプリケーションとツールの更新

## 更新の条件

### アプリ本体

- `Info.plist` の `CFBundleShortVersionString` と `CFBundleVersion` を、公開先の `update-info.json` と比較する。
- セマンティックバージョンを先に比べ、同じ場合だけビルド番号を比べる。
- 更新情報はGitHubの「Latest」にある通常リリースから取得する。

```text
https://github.com/treetips/tree-image-optimizer/releases/latest/download/update-info.json
```

### ツール

- `tools-info.json` の各ツールバージョンと、ローカルの `tools/.installed.json` を比較する。
- 差分があるツールだけを更新する。バージョンが同じでもバイナリが欠けている場合は、初回起動の修復対象になる。
- ツール情報はアプリ本体とは別の `tools-latest` から取得する。

```text
https://github.com/treetips/tree-image-optimizer/releases/download/tools-latest/tools-info.json
```

## 配布物

- アプリRelease: アプリZIP、`update-info.json`、`SHA256SUMS.txt`
- ツールRelease: ツール単位ZIP、`tools-info.json`、`SHA256SUMS.txt`
- ツールReleaseは事前リリースとし、アプリの「Latest」を隠さない。
- 詳細は [リリースフロー](../release-flow.md) を参照する。

## 更新確認の起動経路

- アプリケーション起動時
  - バックグラウンドでアプリ更新を確認する。ダイアログは表示しない。
  - ツールの初回準備が完了してから、ツール更新も1回だけ確認する。
- macOSメニューバーの `Tree Image Optimizer` → `更新を確認`
  - アプリ更新を手動で確認する。更新なし・失敗時はダイアログを表示し、成功時はヘッダーの統合更新カードにも反映する。
- About画面の `アップデートを確認`
  - メニューバーと同じアプリ更新確認を行う。

## ヘッダーの更新ボタン

ヘッダー右端に表示する更新ボタンは1個だけにする。文言は利用可能な更新に応じて次の3種類に限定する。

| 更新の状態           | ボタン文言                       |
| -------------------- | -------------------------------- |
| アプリとツールの両方 | `アプリとツールの更新があります` |
| アプリのみ           | `アプリの更新があります`         |
| ツールのみ           | `ツールの更新があります`         |

- ボタンはカプセル型Liquid Glassとし、ラベルとアイコンを1行に表示する。
- ツールバーに圧縮されない固有サイズを保ち、左端に状態アイコン、右端に操作ピルと閉じるボタンを置く（ADR 0079）。
- アプリとツールの両方に更新がある場合は青背景にする。
- `ダウンロード` / `インストール` の操作ピルから更新を開始する。両方ある場合はツールを先に更新します。
- 変換中は更新ボタンを無効化し、ツール更新中は変換の実行・ドロップを受け付けません。
- ツールの確認が完了するまでは、アプリだけの更新文言を表示しない。

## インストールの流れ

1. 更新ボタンをクリックすると、該当する更新を開始する。
2. 両方ある場合はツールを先に更新する。
   - ツールごとにZIPをダウンロードし、SHA-256を検証して展開・配置する。
   - 成功したツールからローカル記録を更新する。
   - ツール更新に失敗した場合はアプリ更新を開始しない。
3. ツールだけの更新は、完了してもアプリを再起動しない。
4. アプリ更新はZIPをダウンロードし、SHA-256を検証して展開する。
5. 展開したアプリはApplication Supportへステージングし、緑色の `アップデート完了` カードを表示する。
6. `アプリ再起動する` をクリックすると、新しいアプリを `/Applications` へ配置して起動し、旧プロセスを終了する。
7. 失敗時は赤い `インストールに失敗` カードと `再実行` ボタンを表示する。未完了の更新を同じ順序でやり直す。

## 進捗と再起動待ち

- アプリのダウンロード中は円形の進捗表示と `ダウンロード中... n%` を表示する。総バイト数が不明な場合は不確定スピナーにフォールバックする。
- 検証・展開・ステージング中は段階名と不確定スピナーを表示する。
- ツール更新中は対象ツール名とツール単位の進捗を表示する。
- インストール中・再起動待ち・再起動中は、ヘッダーに更新操作を追加しない。
- ステージング済みアプリは次回起動時に掃除する。

## 更新なし

- アプリとツールの両方に更新がない場合は `アップデートは有りません` を表示する。
- 閉じるボタンで非表示にし、10秒後にも自動で非表示になる。
- 確認失敗時は「更新なし」と誤解させないため、既存の更新カードを上書きしない。

## 初回ツール準備

- 初回起動でツールが不足している場合は、開発用ローカルコピーからの修復を先に試す。
- ローカルコピーが使えない場合は `tools-latest/tools-info.json` から不足ツールを取得する。
- 準備が完了するまで操作をブロックし、完了後に日常のツール更新確認を開始する。
