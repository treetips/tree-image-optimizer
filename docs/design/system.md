# システム

## アプリケーション形態

- デスクトップアプリ。
- macOSのみ対応。

## アーキテクチャ

- Apple推奨のObservationベースの構成を採用します。依存関係は View -> Model -> Service の一方向です。
  - View: 宣言的UI。表示に必要な最小限のローカル状態のみを持ち、業務状態は持たずModelの公開状態を表示と操作に結びつけるだけにします。
  - Model: 観測可能な画面状態と操作を持ち、Serviceを呼び出します。
    - 画面固有のフォーム状態（フォルダパス・変換設定・表示フィルタ）は各画面のModelが持ちます。
    - 画面遷移を跨いで存続すべき実行状態（実行中・進捗・結果表）は共有のジョブ層が持ちます。実処理はServiceに委譲し、各画面のModelはファイル列挙と設定スナップショット作成に専念します。
    - かんたん変換のModelは、共有ジョブ層の実行状態を読み取り専用で公開します。
  - Service: 永続化・外部プロセス・OSフレームワークの薄いラッパー。スレッド安全に実装し、UIの判断ロジックを持ちません。
  - Core: 機能横断の共有物。データ定義、エラー型、テーマ・共通View、言語解決を置きます。

- UseCase / Repository 層は設けません。必要なオーケストレーションは変換オーケストレーションのようなServiceに集約し、層を薄く保ちます。

## 状態管理

- 観測可能な状態で管理し、Single Source of Truthを保ちます。状態は使う場所に最も近い層で所有します。
- 共有状態（設定・アプリ本体の更新確認・一括変換ジョブ・かんたん変換ジョブ）はアプリのエントリポイントで生成し、下位Viewへ渡します。画面固有の状態は各Viewがローカルに持ちます。
- 一括変換・かんたん変換の実行状態は各Viewで新規生成しません。ルート画面が共有のジョブ層を保持し、各画面とサイドナビに同一インスタンスを渡します。画面切替でViewが再生成されても実行中・進捗・結果が維持され、ガードレールなしで画面遷移しても孤児タスクになりません。
- サイドナビは各ジョブの実行状態を購読し、実行中はメニューのアイコンをテーマカラーのローディング表示に切り替え、ラベルの下端の最背面に細いリニアバーを重ねて表示します。背景として重ねるためレイアウトに参加せず、行の高さは変わらないので下の項目はズレません。一括変換は進捗連動の確定バー＋右端のテーマカラー進捗%、かんたん変換は不確定アニメーションバーのみ（1ファイルのため%なし）です。行は縦パディングで行高を確保し、内容は中央揃えになります。画面に戻った際は実行中のまま表示します。一括変換の実行ボタンは実行中に `変換中...` のまま非活性にします。処理が終了すれば元のアイコンに戻し、進捗%を非表示にします。
- かんたん変換の入力エリア（ドロップ・クリック選択）はジョブ実行中は無効化し、終了で自動的に有効に戻します。標準の無効化だけではネイティブのドラッグ受け付けまで止まらないため、ドロップ受け付け側でも実行中の入力を受け付けません。
- 現行実装はSwift 6言語モードです。UI状態はメインスレッドに隔離し、Serviceはスレッド安全にして、非同期処理は構造化並行処理で記述します。

## Linter・Formatter

- Linterは [SwiftLint](https://github.com/realm/SwiftLint) を使う。設定はリポジトリ直下の `.swiftlint.yml` で管理する。
- Formatterは [swift-format](https://github.com/swiftlang/swift-format) を使う。設定はリポジトリ直下の `.swift-format`（JSON）で管理する。
- 導入方法:
  - swift-formatはXcode 16以降のツールチェーンに同梱されており、追加インストールなしで `swift format` として実行できる。
  - SwiftLintはHomebrewで導入する（`brew install swiftlint`）。ホストへのインストールを前提とする。
- 実行手順（AGENTS.md「ビルド・テスト・検証方法」の順序に従う）:
  1. `swiftlint` で規約違反を検出・修正する（自動修正は `swiftlint --fix`）。
  2. `swift format format -i -r TreeImageOptimizer` でフォーマットする（確認のみは `swift format lint -r TreeImageOptimizer`）。
  3. フォーマット後は `xcodebuild` でビルドし、コンパイルエラーが無いことを確認する。
- MarkdownのLinter・Formatterは [rumdl](https://rumdl.dev/) を使う。設定はリポジトリ直下の `.rumdl.toml` で管理する。導入はHomebrew（`brew install rumdl`）。
  - Markdownを修正した場合は `rumdl fmt` でフォーマットし、`rumdl check` でlintチェックして違反があれば修正する。
  - GitHub Actions（`.github/workflows/markdown.yml`）でも `rumdl check` と `rumdl fmt --check` を実行し、違反があるとCIに失敗する。対象は `.opencode`（同梱スキル文書）と `tools`（同梱ツールの付属文書）を除くすべてのMarkdown。

## アップデート

- 起動時にバックグラウンドで更新を確認し（ダイアログなし・サイドナビ通知のみ反映）、About画面・メニューバー・サイドナビ通知から手動確認もできます。手動確認の結果はダイアログとサイドナビ下部の更新カードの双方に反映します（確認失敗時は更新カードを変更しません）。
- アプリ本体の更新は、GitHub Releasesの `update-info.json` を取得し、セマンティックバージョン→ビルド番号の順で比較します。GitHub側が新しい場合のみアップデートダイアログを表示します。
- ダウンロード・SHA-256検証・展開・`/Applications` への適用・再起動まで一連の更新処理で行います。ダウンロードは受信バイト数から進捗率を求め、検証・展開・コピーは不確定表示にして、サイドナビの「インストール中」カードへ反映します（ADR 0050）。
- 外部ツールはアプリ本体と独立して更新します。起動時に `tools-info.json` を取得し、`tools/.installed.json` との差分だけをツール単位ZIPで更新します。アプリ本体ZIPは tools を同梱せず、ツール更新でアプリは再起動しません（ADR 0064）。

## サウンドの再生

- OS標準の音声再生機能を使います。音声ファイルはアプリのリソースとして同梱します。
- 再生対象のフォルダは以下の通りです。
  - アプリバンドル内の `assets/sounds/success`。最初から同梱されている成功音声のフォルダで、必ず音声ファイルが配置されています。
  - アプリバンドル内の `assets/sounds/error`。最初から同梱されている失敗音声のフォルダで、必ず音声ファイルが配置されています。
  - `~/.config/tree-image-optimizer/sounds/success`。ユーザーが任意に配置する成功音声のフォルダです。
  - `~/.config/tree-image-optimizer/sounds/error`。ユーザーが任意に配置する失敗音声のフォルダです。

## 通知

- OS標準の通知機能を使います。起動時に許可を求め、アプリ前面表示中もバナーを出します。

## 国際化

- OS標準のローカライズ機構を使い、日本語と英語の文言カタログを持ちます。画面のロケール環境が届かない箇所（メニュー・通知・ダイアログ文言）は、設定言語に従う共通の文言解決を通します。

## アプリケーション

- アプリケーションアイコンはバンドル内の `Resources/TreeImageOptimizer.icns` を使用します。
- About画面の表示アイコンは `assets/images/icon-tree-01.png` を使用します。
